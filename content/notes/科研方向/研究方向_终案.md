# 面向边缘硬件感知的多目标进化神经架构搜索研究方案

## 核心问题

RK3566 边缘端算力严重受限（CPU: 4×Cortex-A55, NPU: 0.8 TOPS），如何在精度和推理延迟之间自动找到最优平衡，打破手工架构的瓶颈。

## 量化目标

| 目标 | 最低要求 | 理想值 |
|---|---|---|
| 鸟鸣分类 Top-1 Accuracy | > 80% | > 90% |
| RK3566 单次推理延迟 | < 50ms | < 20ms |
| 模型参数量 | < 2M | < 500K |
| 模型存储大小（INT8量化后） | < 5MB | < 1MB |

### 数据预处理 pipeline

```
原始音频（.mp3/.wav）
  ↓ resample 到 16kHz, 截取/补齐到 10s
  ↓ 数据增强（训练集）：
  │   - 时间拉伸（0.8x ~ 1.2x）
  │   - 频率掩蔽（FrequencyMasking, 最多 16 个 mel bin）
  │   - 时间掩蔽（TimeMasking, 最多 20 帧）
  │   - 背景噪声混合（从噪声类随机选取，SNR 5-15dB）
  ↓ mel-spectrogram（128 mel bins, 128 帧, hop_length=10s*16000/128）
  ↓ 归一化（per-channel z-score）
  ↓ 保存为 .npy，形状 (128, 128)，单通道
```

## 搜索空间定义（核心）

### 宏观架构编码

每个个体用一个整数向量表示，共 16 维：

```
编码位置  参数              取值范围            #取值
──────────────────────────────────────────────────
 0      stem_channels      [16, 24, 32]         3
 1      n_stages           [2, 3, 4]            3
 2      stem_stride        [1, 2]               2
 3      n_layers@stage0    [2, 3, 4]            3
 4      n_layers@stage1    [2, 3, 4]            3
 5      n_layers@stage2    [2, 3, 4]            3
 6      kernel@stage0      [3, 5]               2
 7      kernel@stage1      [3, 5]               2
 8      kernel@stage2      [3, 5]               2
 9      expand@stage0      [1, 2, 3, 4]         4
10      expand@stage1      [1, 2, 3, 4]         4
11      expand@stage2      [1, 2, 3, 4]         4
12      use_se@stage0      [0, 1]               2
13      use_se@stage1      [0, 1]               2
14      use_se@stage2      [0, 1]               2
15      activation         [0(relu), 1(hswish)] 2

总搜索空间大小: 3×3×2×3³×2³×4³×2³×2 ≈ 7,077,888 ≈ 707 万
```

### 微观构建块（每个 stage 内的搜索单元）

```python
class SearchBlock:
    """
    倒残差 + 可选 SE + 可选跳跃连接
    MobileNetV2 block 的搜索版本
    """
    def __init__(in_ch, out_ch, kernel, expand, use_se, act, stride):
        # 1. 1×1 expand（如果 expand > 1）
        # 2. depthwise conv (kernel × kernel)
        # 3. SE (如果 use_se == 1)
        # 4. 1×1 project (恢复到 out_ch)
        # 5. skip connection (如果 in_ch == out_ch and stride == 1)
```

### 搜索空间设计理由（面向时频稀疏信号）

```
设计决策                          针对的声学特性
─────────────────────────────────────────────────
kernel 可选 3 或 5                鸟鸣音节需要更大感受野捕获频率邻域
expand 可选 1-4                  时频稀疏 → 不需过宽的中间表示
SE 可选                           不同鸟种的关键判别频带不同（注意力）
skip connection 有条件            保持浅层时频细节的传递
stem_stride 可选 1 或 2           控制早期下采样程度（保留高频细节）
```

## 评估指标体系

### 分类性能

| 指标 | 用途 |
|---|---|
| Top-1 Accuracy | 主要指标 |
| Macro F1 | 类不平衡时的补充 |
| Per-class Recall | 分析哪些鸟种最难识别 |

### 硬件效率

| 指标 | 测量方式 |
|---|---|
| 推理延迟 (ms) | RKNN Toolkit 在 RK3566 上实测 |
| 参数量 | PyTorch `sum(p.numel())` |
| FLOPs | thop / fvcore |
| 模型大小 (MB) | INT8 量化后的 .rknn 文件大小 |

### 搜索质量

| 指标 | 说明 |
|---|---|
| Hypervolume (HV) | 主指标，参考点 (acc=0.6, latency=100ms) |
| IGD | 需要先跑一个超大规模的搜索得到近似真实前沿 |
| C-metric (Coverage) | 两个算法互相覆盖的比例 |
| Spacing | 前沿的均匀性 |

### 统计检验

所有对比实验必须做统计检验：

- Wilcoxon 秩和检验（p < 0.05）
- 每个实验独立重复 5 次，报告 mean ± std
- 多组比较用 Friedman 检验 + Nemenyi post-hoc

## 算法改进

### 改进 A：硬件感知种群初始化

标准的 NSGA-II 用完全随机的方式生成初始种群，这意味着第一代个体在参数量、FLOPs 和延迟上的分布是均匀随机的，前沿面从一片混沌开始，收敛需要更多代数。

改进 A 的核心思路是**把"硬件约束"前置到种群诞生之前**。具体做法是把初始种群切成三块：

1. **轻量子种群**（约占 1/3）：限制 stem_channels 取小值（16/24）、expand ratio 压低（1~~2）、kernel 固定为 3、n_layers 偏向浅层（2~~3）。这一批个体天生就小、快，初始就在低延迟区域落点。
2. **重量子种群**（约占 1/3）：stem_channels 取大值（24/32）、expand ratio 拉高（3~~4）、n_stages 固定为 3、n_layers 偏向深层（3~~4）。这一批天生精度高，初始就在高精度区域落点。
3. **中等子种群**（剩下 1/3）：不做任何约束，随机生成，填补中间地带。

这样一来，**初始种群的 Pareto 前沿就已经有了大致形状**——低延迟个体和高精度个体分别在两端，随机个体分布在中间——后续进化在这个基础上逐步逼近真实前沿，而不是从零开始。书中对这个改进的检验标准也很明确：分层初始化的初始 HV 必须显著高于纯随机初始化（Wilcoxon p < 0.05）。

### 改进 B：代理模型辅助进化

标准 NSGA-II 里，每个个体的适应度来自"完整训练 50 个 epoch → 真实评估 accuracy"。如果种群规模 40、跑 50 代，这意味着几千次完整训练，在实验室 GPU 上代价极高。

改进 B 把评估拆成**快路径和慢路径两条线**：

**快路径（日常评估）**：一个新个体被解码成模型后，只训练 5 个 epoch 得到一个"早停 accuracy"。然后这个早停精度连同架构编码（stem_channels、n_layers 等 16 维向量）一起送入一个预训练的**精度预测器**（本质是一个回归模型），输出最终精度的预测值。延迟侧同理，一个延迟预测器直接用架构编码输出预测延迟。整个过程不涉及完整训练和硬件实测，单次评估成本降到原来的 1/5 以下。

**慢路径（定期校准）**：每若干代（如每 5 代），挑出当前 Pareto 前沿上最好的 5 个个体，对它们执行完整 50-epoch 训练和硬件实测，拿到真实 accuracy 和真实延迟。这些少量真实值被追加到校准数据集里，对精度预测器做增量更新。这一步的意义在于**防止预测器漂移**——搜索越到后期，遇到的新架构离原始训练集越远，预测误差会积累，定期校准把预测器拉回真实分布。

**离线阶段**还需要先跑一次性的数据采集：随机采样约 300 个架构，对它们完整训练并记录真实 accuracy，训练出初始的精度预测器。

这一套的净效果是：在总评估预算基本不变的前提下，搜索算法能探索的个体数量大幅增加，因为大部分评估走了廉价代理路径，只有少数关键个体消耗了昂贵的完整训练预算。
